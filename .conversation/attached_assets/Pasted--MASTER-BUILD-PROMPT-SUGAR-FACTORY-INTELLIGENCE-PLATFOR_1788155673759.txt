# MASTER BUILD PROMPT — SUGAR FACTORY INTELLIGENCE PLATFORM

You are the lead software architect, senior backend engineer, senior frontend engineer, data engineer, DevOps engineer, QA engineer, and product manager for this project.

You are building a production-quality **Sugar Factory Intelligence Platform** based on the product specification below.

Your job is NOT to create a superficial demo.

Your job is to build the foundation of a real SaaS product that can ingest real Indian sugar-mill Excel files, preserve the original source data, normalize different workbook formats into a canonical factory schema, calculate deterministic KPIs, detect anomalies, generate an auditable daily management report, and eventually support an AI factory analyst.

---

# 1. PRODUCT VISION

A sugar mill produces many Excel workbooks every day.

Typical reports include:

* Production
* Cane Crushing
* Sugar
* Recovery
* Quality
* Downtime
* Boiler
* Steam
* Power Generation
* Power Used
* Maintenance
* Inventory
* Chemicals
* Dispatch
* Shift Log
* Laboratory

The platform must turn these fragmented Excel files into:

> **One reliable, traceable daily intelligence report for factory management.**

The factory should NOT need to change its existing workflow.

Files can arrive through:

* Web upload
* Watched folder
* Factory email attachment

The fundamental product principle is:

> **Files land → intelligence appears.**

The platform must preserve every original file and make every reported number traceable back to its source.

The product is deliberately sequenced:

PHASE 1:
Automated Daily Report

PHASE 2:
Factory Intelligence

PHASE 3:
AI Factory Analyst

PHASE 4:
Predictive Intelligence

Do NOT prematurely build Phase 3 or Phase 4 before the Phase 1 data foundation is reliable.

# 2. NON-NEGOTIABLE ENGINEERING PRINCIPLE

The hardest and most valuable part of this product is the data layer.

DO NOT build:

"LLM + Excel files = chatbot"

Instead build:

Raw Files
→ File Registry
→ Hash / Deduplication
→ Parsing
→ Column / Sheet Mapping
→ Validation
→ Canonical Factory Schema
→ Deterministic KPI Engine
→ Historical Baselines
→ Rule-Based Anomaly Detection
→ Daily Report
→ Dashboard
→ AI layer later

The AI must NEVER become the source of truth for numerical calculations.

For example:

Recovery = Sugar Produced / Cane Crushed

This must be calculated deterministically in SQL/Python.

The LLM may explain the result.

The LLM may NOT invent or calculate critical factory numbers when deterministic data exists.

Every AI-generated statement should ultimately be grounded in structured data and/or source reports.

# 8. FILE INGESTION SYSTEM

This is one of the most important components.

The system must accept Excel files.

Supported initially:

* .xlsx
* .xls where technically practical

For every incoming file:

1. Receive file.
2. Calculate SHA-256 hash.
3. Check whether the exact file already exists.
4. If duplicate, do not process it twice.
5. Store the original file immutably.
6. Create a file registry record.
7. Record metadata.
8. Parse workbook.
9. Detect sheets.
10. Inspect headers.
11. Detect likely report type.
12. Map the file into the canonical schema.
13. Validate.
14. Store structured data.
15. Record processing status.
16. Record errors/warnings.
17. Preserve complete lineage.

Raw files must NEVER be overwritten.

Raw files must NEVER be silently deleted.

# 23. PHASE 3 — AI FACTORY ANALYST

Only build this after the structured data foundation is reliable.

The AI analyst should support questions such as:

"What happened to recovery yesterday?"

"Why did recovery decline?"

"How has downtime changed this season?"

"When did we last see a similar recovery level?"

"What were the biggest production issues this week?"

The AI system should:

1. Understand the question.
2. Determine whether it needs SQL, document retrieval, or both.
3. Query structured data where possible.
4. Retrieve source reports where necessary.
5. Perform deterministic calculations outside the LLM.
6. Generate an explanation.
7. Attach citations/source references.
8. Clearly identify uncertainty.

The AI must NEVER invent factory numbers.

If information is unavailable:

Say that it is unavailable.

Do not guess.
